# Investigation workspace

The shell mounts `App.tsx`; `SupportPlatform` owns fictional tickets and the existing `InvestigationWorkspace` owns each active investigation. `investigation.ts` defines the workflow and orchestrates validated, read-only `invokeRead` calls. `operations.ts` validates responses and suppresses unsafe errors; `safeEvidence` selects permitted output fields. The SDK task is started by the shell-facing app and direct calls are bounded by a local timeout. The support repository verifies the fictional ticket binding in browser memory.

The workspace derives a graph view from the investigation record, with selection local to the keyed workspace. The canvas and inspector share that selection and the diagnosis reads the same record. The ticket context is supplied by the support view. Workflow edges describe configured dependencies; the application observes calls, including parallel logs and blocks, but the engine does not provide per-node trace telemetry here. Times are application-observed, not engine timestamps. No cancellation, retry count, invocation ID or engine run trace is asserted.

Reuse the existing React Flow, evidence normalization, identity checks, offline client and ticket repository. Separate display execution status from diagnostic severity without changing the orchestration's legacy warning state. Retain completed fictional records only in session memory so linked investigations can be reopened. A keyed workspace prevents selection from crossing tickets; a new run resets selection.

Inspector inputs and outputs must be field-filtered and secrets redacted before display; raw disclosure is the sanitized normalized result, not the original response. AI remains opt-in and clearly identified as interpretation. Client-side scope and identity checks are correctness checks, not production authorization. No browser persistence or account writes are added. The accessible step list supplements React Flow keyboard support. Responsive panels stack when space is constrained. Real tenant storage, shell integration and live engine behavior remain unverified.
