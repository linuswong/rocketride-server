# Current state and capability audit

Audited 2026-11-18 against this checkout, not a connected engine. `apps/auth0-operations-ui` is an App Builder React/TypeScript shell app, with a `local.auth0-operations` manifest and a `.rrapp` trigger. The shell owns authentication and the SDK connection. `App.tsx` starts or reuses `investigation.pipe`; direct `client.tool` calls to `tool_auth0_1` supply the graph. `investigation.ts` sequences exact-email search, unique-match check, profile, parallel logs and brute-force blocks, then model interpretation. React Flow renders application-observed request boundaries, not internal Auth0 calls. `reviewWorkflows.ts` provides read-only identity and security views. Existing chat and recovery review should remain available.

`investigation.pipe` contains chat, Wave agent, answer, memory, Gemini model and Auth0 tool; `synthetic_investigation.pipe` is a separate tool-free model pipeline used for interpretation. Despite its name, the latter can receive filtered live evidence. Secrets are RocketRide environment references. The checked-out Auth0 node is experimental: availability and credentials on a connected engine have not been verified. Its README describes 18 read tools: search_users, get_user, get_user_logs, get_log_event, get_user_blocks, get_connection, list_connections, get_connection_clients, list_users, list_applications, search_logs, get_brute_force_settings, get_ip_throttling_settings, list_roles, get_user_roles, get_user_permissions, list_organizations, get_organization_members. It documents one-page results, scope requirements and sanitized output; writes remain unavailable. Check its README and implementation for exact schemas. No claim is made about PR merge state or an installed server.

Existing normalization validates expected shapes and allowlists graph fields. An empty log page is inconclusive, administrative and brute-force blocks are distinct, and model output is explicitly unverified. React Flow is already a dependency. Existing tests use deterministic SDK mocks. Data stays in component memory; reload loses it. The original synthetic demo requires an engine and model credentials. There is no demonstrated tenant-scoped persistence or audit trail in this app, so browser storage must not be treated as an access-control boundary. The dashboard's previous assistant-response count is not a count of graph investigations.

Subsequent work added a separate credential-free offline graph example, keyboard support and an isolated Chromium component test. The dashboard no longer presents assistant responses as an investigation count. The shell component resets its in-memory state on disconnect or reported user/organization change; this does not establish server-side isolation. See `../progress.md` for the current verification status.

RocketRide supports TASK/SUMMARY/FLOW monitoring and metadata traces, but this graph's states are direct frontend SDK call boundaries and local decisions, not engine trace events; they cannot expose Auth0 retries or prove backend ordering. More granular progress would require correlatable per-invocation engine events and careful handling of sensitive trace payloads. Keep the existing direct-call workflow and read-only safeguards; improve validation, evidence presentation, offline verification, error handling and truthful UI. Do not split the existing pipeline just to create more pipelines. The experimental node's eligibility for the public catalog and a connected server's exact capabilities remain release blockers.
