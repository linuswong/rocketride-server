# Identity contract investigation — 2026-11-18

**Decision: no deployable identity architecture is established.** Keep the fictional experience. The candidates below remain proposals, not a claim RocketRide cannot support them. No live provider or authenticated engine was contacted.

## Evidence and boundary

The `.rrapp` contains only the app ID; `package.json` marks the app authenticated. The shell mounts the descriptor (`src/AppDescriptor.ts`), and `src/App.tsx` reads `useAuthUser()` and `useShellConnection()`, remounting on connection, user or organization changes. `packages/shell/src/hooks/useAuthUser.ts` returns a browser context populated from `ConnectResult`; it is presentation state and cannot authenticate a separate service.

Cloud shell `packages/shell/src/auth/CloudAuthProvider.ts` generates PKCE and redirects to Zitadel; its callback returns code, verifier and redirect URI for the engine connection. `packages/client-typescript/src/client/client.ts` sends an `auth` DAP request and caches its response. `types/client.ts` defines `userId`, `organization` with permissions, and `userToken`, described as a short-lived `rr_` reconnect credential; profile responses may contain `memberships`. The token is a bearer credential, not a demonstrated SupportPilot-audience assertion. A browser posting this response or an org ID is not evidence of identity or membership. The shell's auth flag is a UI loading gate, not a backend authorization check.

`packages/client-typescript/src/client/account.ts` sends `rrext_account_me` (`get`) and `rrext_account_members` over the authenticated connection. `packages/ai/src/ai/modules/task/commands/cmd_account.py` delegates to the account provider; SaaS business logic is an external overlay absent from this checkout. Thus we cannot inspect whether profile or membership reads revalidate a session and membership on each call, revocation propagation, race behavior, or which roles may list members. `packages/ai/src/ai/account/oss/__init__.py` authenticates the configured API key, synthesizes a single local developer and local organization, and implements only environment account commands; it accepts connections without a configured key. It is not a multi-tenant membership authority. Do not send shell bearer credentials to an unrelated service on the assumption that this is supported.

No app-specific signed assertion, SupportPilot issuer, audience, JWKS, key rotation, expiry or introspection contract was established. OAuth PKCE and the reconnect token do not by themselves establish those properties. Their exact SaaS issuance and revocation semantics are unknown here; no JWT verification claim is made. `packages/shell/src/workspace/workspaceStore.ts` writes workspace partitions with `fsWriteJson`, debounced and with errors caught. That supplies app state, not proven transactional organization-level record isolation. App credentials in `src/investigation.pipe` are environment references; provider isolation and permission are deployment-specific, and the investigated Auth0 customer is not the operator.

## Options

* **A: platform delegation (preferred subject to proof).** RocketRide may offer either a documented SupportPilot-audience token plus signature/issuer/audience/expiry and current membership verification, or a supported server-to-server session validation and membership check. Evaluate the existing `rr_`/account APIs with platform owners: delegation, secure token transfer, server origin pinning, expiration, invalidation, permissions, current membership and revocation races are unproven. The mere existence of these APIs does not satisfy the gate.
* **B: trusted RocketRide boundary.** DAP handlers are engine-side but this app supplies a browser bundle and pipeline; no supported app-owned authenticated route or transactional app database extension was found. Upstream could provide an app-scoped server handler with verified current principal, organization, permission and transactional store; it must prevent caller-controlled scope and recheck revocation. This needs platform design and no shared engine changes are included.
* **C: separate established OIDC provider.** Not selected: provisioning, authoritative org membership, RocketRide identity linking, unlink/revocation, session expiry, onboarding and operational ownership are all unknown. A second login alone cannot prove RocketRide organization membership.

Minimum unblock: platform owners document and demonstrate a supported delegated credential or trusted handler, allowed issuer/audience, verification/key rotation and expiration, origin binding, current membership/permissions and revocation consistency; provide an authorized test tenant and independently exercise valid, expired, wrong-audience, revoked and cross-tenant cases. Define how concurrent revocation interacts with commits. If no platform solution exists, separately agree on provider, provisioning and lifecycle before choosing C.

The [Shell API](https://docs.rocketride.org/guides/apps/) documents PKCE, identity props and workspace state; [MCP connection](https://docs.rocketride.org/connect/mcp/http/connect/) documents credentials for MCP, not delegation to SupportPilot. Neither establishes this app's backend contract.
