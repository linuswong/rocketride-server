## Browser test

From this folder run `pnpm exec rsbuild build --config test/browser/rsbuild.config.mts`, then `node --test test/browser/browser.test.mjs`. This uses a temporary loopback HTTP server and a headless Chromium browser (Edge on Windows; set `SUPPORTPILOT_BROWSER` to another Chromium executable when needed). It exercises the real workspace component in an isolated test host with a fake client, not the RocketRide shell. It checks offline data, graph selection and keyboard interaction, evidence, input and startup errors, delayed mocked state changes, and a 375px layout. It is not a complete accessibility audit or an App Builder end-to-end test. The build output is ignored.

## Optional live smoke test

Do not run against production. First obtain explicit permission for read-only calls, possible engine/provider charges, the designated development tenant and test subject. Configure the engine's Auth0 environment references as described in the app README, with the experimental node installed and writes disabled. Starting the existing pipeline may initialize its configured model provider even though this harness never sends model chat; costs cannot be ruled out. Do not print or commit credentials or customer data.

In a private PowerShell session, set `$env:ROCKETRIDE_URI` and `$env:ROCKETRIDE_APIKEY` to the development engine, set `$env:SUPPORTPILOT_TEST_SUBJECT` to the designated test email or user ID, and only after that authorization set `$env:SUPPORTPILOT_LIVE_CONFIRM = 'NONPRODUCTION_READ_ONLY_AND_POSSIBLE_COSTS'`. From the app directory run `node --experimental-strip-types test/live-smoke.mjs`. It starts a fresh short-lived task, verifies the running Auth0 node's read-only setting, executes the same direct-read orchestration without AI analysis, prints step states only, and requests termination. Missing/ambiguous accounts and incomplete checks are failures. Remove those session variables afterward. Run with no confirmation to verify the guard without making a connection. The harness does not verify the shell UI, backend retries or provider billing behavior, and has not yet been run with a live tenant.

The mocked suite does not prove actual cancellation, a live server, scopes or provider availability. Follow the app README and node LIVE_TESTING guide for live precautions. Never capture raw responses or identifiers as test evidence.

The browser fixture also exercises fictional ticket creation, classification, an offline investigation, return to the ticket and an editable draft. Unit tests cover input validation, transitions, repository scope checks, safe linking, routing, search and fictional knowledge. These tests do not establish real server authorization or App Builder integration.

## Milestone 5 verification and manual procedures

From the app folder, run `node --experimental-strip-types --test test/*.test.mjs`, `pnpm run build`, `pnpm exec rsbuild build --config test/browser/rsbuild.config.mts`, and `node --test test/browser/browser.test.mjs`. The last uses local loopback; sandbox restrictions may block it. `test/boundary.test.mjs` tests a server-side *model* with simulated identities and mutable memberships, not the actual authorization of a deployed server. The contract types are not runtime validation. Build output does not verify an install.

For App Builder, follow the numbered **Manual verification in App Builder** in the README: open the `.rrapp` with the VS Code RocketRide extension, wait for pnpm and the Design preview, and run the fictional flow. Record shell/extension and engine versions, preview success, graph and inspector outcomes, and any errors without recording customer information. Check Errors and watch output if it fails. The separate headless fixture is not this test. A built engine executable existing on disk does not establish a running or authorized engine.

For a live baseline, first explicitly establish an authorized non-production engine and non-production Auth0 tenant, a designated synthetic subject, least-privilege scopes, permission for read-only calls and approval for possible model-provider costs. Configure engine environment references and keep `allowWrite` false. The pipeline may initialize its provider even with AI interpretation disabled. Set the four variables and confirmation exactly as in **Optional live smoke test** above. Expected: guard refuses before connecting without confirmation; with authorization the script prints step states, and profile/logs/blocks must complete or warn. A missing, ambiguous or mismatched subject, failure, timeout, insufficient scope or malformed response is not a successful smoke test; inspect engine and node diagnostics privately. The test requests termination in `finally`; a timeout or termination failure leaves remote status uncertain. Check the engine task list and terminate the test task through authorized engine administration if needed. Collect only sanitized pass/fail, versions, timestamps and confirmation of read-only configuration; remove the process environment variables afterward. Never save raw evidence or secrets. This procedure is not live-verified here.
