# Security and data handling

Milestone 6 found no verified delegated identity and current-membership contract for SupportPilot. The schema experiment does not authorize access, and even an authenticated RocketRide connection or a browser-provided organization is not proof to a separate backend. No raw Auth0 evidence, drafts, or real ticket data should be placed in it. See [identity investigation](architecture/identity-contract-investigation.md).

The app is read-only; Auth0 credentials are configured as RocketRide environment references and are not entered in the UI. Live analysis sends selected customer data to the configured model provider; review tenant authorization, data handling and scope before enabling it. Tool output and questions are untrusted, and prompt instructions are not a proof of injection resistance. A model cannot authorize actions here. The node and app filter fields, but error paths and all other views still require a complete independent security review.

Records are currently memory-only and disappear on refresh. No claim of application-level tenant isolation, auditing or secure persistence is made. SDK timeouts do not cancel remote requests. Raw tool and trace data may contain sensitive information; do not retain or publish it without an approved policy. Do not use production tenants for testing.

The app remounts its in-memory workspace on shell disconnect or reported user/organization change, reducing accidental carryover; this is not a server authorization boundary and does not prove isolation or cancel in-flight remote requests. The graph's live model analysis is off by default. The separate AI Assistant and older synthetic AI demo make model requests when explicitly used; the named-tool chat path displays node output and needs a broader field-level redaction audit. Never interpret a prompt instruction as a security boundary. The SDK read timeout is a local wait limit: late remote work may continue, and no automatic retry is performed. Starting a new investigation repeats read calls; there is no cancellation button or guarantee that a previous timed-out call has stopped.

The support inbox is explicitly fictional, memory-only and scoped to a synthetic session. Its repository rejects a mismatching scope on all methods and checks ticket ID, status, category and the fixed fictional account when linking a demo investigation. These checks prevent accidental cross-scope use in normal code; a client-side caller can forge its own scope or mutate the program and therefore they are not tenant authorization. The support demo must not receive real customer data. A production backend must authenticate and authorize every operation server-side, bind a specific investigation to an authorized ticket independently of an email match, and provide retention, deletion, auditing and migrations. No outbound send exists. Local knowledge articles and draft text are fictional, and no support-demo text is sent to an LLM.

## Investigation inspector

Inspector inputs are restricted to expected identifiers; outputs use the existing field allowlist and redact common credential patterns in permitted strings. Expandable JSON is the sanitized normalized output, never the raw provider response. This is defense in depth, not a guarantee that arbitrary free text contains no sensitive information; a full redaction review and server-side data minimization remain necessary before production use. Trace times are observed by the browser and cannot establish remote cancellation or engine activity. Fictional investigation records remain in memory and are discarded with the session. Reopening is limited to the associated fictional ticket; browser checks do not provide authorization.

## Milestone 5 threat model

See [authentication and authorization](architecture/authentication-authorization.md) for cross-tenant exposure, ID guessing, credential leakage, evidence export, prompt injection, revoked access, incorrect links, retries, model sharing and retention. The Node test harness is a simulated trust boundary, not a deployed service. No production security guarantee follows from its passing tests. Shell identity and organization values in React cannot authorize a separate service. Credential environment references do not prove per-tenant engine secret isolation.
